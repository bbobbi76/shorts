# 세부기능 간략설명

## 영상·이미지 확인과 업로드

브라우저 File API와 HTML video의 loadedmetadata로 선택한 파일의 기본 정보와 영상 재생시간·크기를 확인합니다. 썸네일은 이미지 로딩 성공 여부를 확인합니다. 파일은 FormData로 전송하며 별도 업로드 플러그인은 사용하지 않았습니다. 사용자가 등록 전에 파일을 확인하고 잘못된 파일을 바꿀 수 있도록 선택했습니다.

미리보기에는 URL.createObjectURL을 사용하고 교체·화면 종료 시 URL.revokeObjectURL로 임시 주소를 해제합니다. 이 주소는 서버 파일 주소가 아니며 DB에 저장하지 않습니다. API 모드에서는 보호된 파일을 쿠키와 함께 조회한 후 미리 봅니다.

참고: [MDN Blob URL](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/blob), [URL 해제](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static).

## 공개 전 필수 항목 검사

공개 요청 전에 과정·제목·영상·퀴즈·정답·해설을 검사하고 누락 목록을 표시합니다. 완성하지 않은 내용은 초안으로 저장할 수 있습니다. 파일·데이터를 먼저 저장하고 공개 상태 변경 요청을 별도로 보내 실패 지점을 구별합니다. 서버에서도 동일 조건과 권한을 다시 검사해야 합니다.

## 실패 시 입력 유지와 중복 요청 방지

입력값은 React 상태로 보관하고 실패 시 폼을 초기화하지 않습니다. 업로드 실패 시 기존 파일을 유지하며 같은 파일을 다시 선택할 수 있습니다. 저장·업로드 중에는 관련 입력과 저장 버튼을 잠급니다. 생성 요청에 ID 기반 Idempotency-Key를 전달하지만 실제 중복 방지는 백엔드 구현이 필요합니다.

로그인 만료 시 편집 화면을 제거하지 않고 로그인 대화상자를 띄워 재로그인 후 이어서 편집하도록 했습니다. 미저장 변경사항이 있으면 다른 화면 이동과 페이지 이탈에 확인을 표시합니다. 브라우저 종료 후 미저장 내용을 영구 복원하는 기능은 아닙니다.

## 로컬 시연 데이터 보존

백엔드가 준비되기 전 화면을 검증할 수 있도록 IndexedDB에 예시 데이터와 Blob 파일을 저장합니다. 문자열 저장소에 대용량 영상을 넣지 않기 위해 선택했습니다. 실제 서버 DB와 구별해 항상 예시 데이터 모드 안내를 표시합니다.

## 검색과 화면 이동

콘텐츠 제목 검색, 과정 선택, 공개 상태 필터를 조합합니다. 실제 API 모드도 초기 전체 목록에 프론트 필터를 적용합니다. 관리자 목록 검색이며 사용자용 상황별 검색 기능과는 구별합니다. React Router를 사용해 등록·수정 페이지와 목록을 이동합니다.

## 반응형과 접근성

작은 화면에서는 사이드 메뉴를 접고 입력 영역을 한 열로 바꿉니다. 긴 목록 표는 내부에서 가로 스크롤합니다. 입력 라벨, 버튼 이름, 오류 alert, 완료 status, 키보드 포커스와 기본 dialog를 사용합니다. React는 입력과 퀴즈를 텍스트로 표시하며 사용자 HTML을 실행하지 않습니다.

개선판에서는 390px 목록 안에 제목·과정·상태·수정 동작을 함께 제공해 필수 정보를 보기 위한 가로 스크롤을 줄였습니다. 오류는 필드의 aria-invalid·aria-describedby와 연결하고 요약으로 포커스를 옮깁니다. 대화상자에 접근 가능한 제목을 연결하고 닫을 때 이전 버튼으로 포커스를 복원합니다. 닫힌 모바일 메뉴에는 inert를 적용하고, 열린 메뉴에서 Tab 순환·Escape 닫기를 지원합니다.
