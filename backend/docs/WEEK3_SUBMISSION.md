# 3주차 백엔드 활동 내용

담당자: 현지민  
백엔드: FastAPI (Python)  
데이터베이스: MySQL 8.0

## 1 개발 범위

이번 주에는 관리자 콘텐츠 관리 기능의 백엔드 API 코드를 작성하고 자동 테스트를 진행했습니다. 실제 MySQL 환경에서의 연동 및 화면 통합 테스트는 후속 작업으로 진행할 예정입니다. 기존 FastAPI 백엔드와 DB 구조, 프론트엔드의 React 관리자 화면을 바탕으로 화면과 서버의 요청·응답 형식을 연결하는 API를 추가했습니다.

구현 범위는 관리자 로그인, 과정·콘텐츠 등록과 수정, 목록·상세 조회, 파일 업로드, 공개·비공개 전환입니다. 사용자 검색, 답안 제출, AI 피드백 생성과 학습 진도 저장은 후속 개발 범위로 구분했습니다. 향후 영상 제목뿐 아니라 자막과 실무 상황을 기반으로 콘텐츠를 검색할 수 있도록 확장할 예정입니다.

## 2 주요 작업 내용

### 프론트엔드와 백엔드 데이터 연결

기존 프론트와 백엔드는 인증 방식, API 경로, 데이터 필드가 달랐습니다. 프론트가 사용하는 과정·콘텐츠·파일 형식을 기존 DB 구조에 맞게 변환하는 `/api/ui` API를 추가했습니다. 프론트엔드와 DB 간 데이터 형식 차이를 백엔드에서 변환하도록 구성했습니다.

### 관리자 로그인과 권한 확인

관리자 로그인 후 HttpOnly 쿠키로 세션을 유지하도록 구현했습니다. 관리자 API를 호출할 때마다 관리자 역할과 계정 상태를 확인하며, 저장·수정 등 변경 요청에는 CSRF 토큰을 검사하도록 했습니다. 세션 유효 시간은 8시간이고 서버를 재시작하면 다시 로그인해야 합니다.

### 과정과 콘텐츠 저장

과정과 콘텐츠를 등록·조회·수정하는 API를 연결했습니다. 콘텐츠에는 영상, 썸네일, 퀴즈, 실습 안내와 첨부자료를 함께 저장하도록 구성했습니다. 소속 과정을 선택하지 않은 초안은 보조 테이블에 보관하고, 과정 선택 후 기존 콘텐츠 테이블에 저장하도록 했습니다.

기존 DB 구조에 화면 연동용 `ui_records` 보조 테이블을 추가하는 코드를 작성했습니다. 이 테이블은 과정 미지정 초안과 화면의 추가 정보를 보관하고, 같은 등록 요청이 반복될 때 중복 생성을 막는 데 사용합니다. 실제 MySQL 테이블 생성은 연동 단계에서 확인할 예정입니다.

### 파일 업로드와 조회

기존 파일 업로드 기능을 프론트의 요청 형식과 연결했습니다. 콘텐츠 저장 시 클라이언트가 보낸 파일 정보만 사용하지 않고 실제 저장된 파일 ID, 종류와 존재 여부를 확인하도록 했습니다.

MP4 파일은 서버에서 재생 시간을 읽습니다. 초안·비공개 파일은 관리자 인증 후 조회할 수 있고, 사용자에게는 공개 과정의 공개 콘텐츠에 연결된 파일만 제공하도록 했습니다.

### 공개 조건 검사

공개 요청 시 제목, 영상, 퀴즈 문제·보기·정답·해설 등 필수 항목을 검사하도록 구성했습니다. 일반 저장 요청에 공개 상태를 넣어도 공개 검사를 우회할 수 없도록 했습니다. 공개 중인 콘텐츠를 수정해 필수 조건이 깨지면 수정 내용을 저장하지 않고 기존 데이터를 유지하도록 했습니다.

사용자용 콘텐츠 조회에서는 관리자용 정보와 퀴즈 정답·해설을 제외했습니다.

## 3 세부 기능과 사용 기술

| 기능 | 사용 기술 | 사용 이유 |
|---|---|---|
| API 구현 | FastAPI | 요청·응답 처리와 입력값 검증, 자동 API 문서 제공 |
| DB 연결 | SQLAlchemy | 기존 MySQL 테이블과 연결하고 관련 데이터의 저장·수정을 처리 |
| 로그인 유지 | HttpOnly 쿠키와 서버 메모리 세션 | 로그인 상태를 유지하고 서버에서 관리자 여부를 확인 |
| 변경 요청 검사 | CSRF 토큰 | 인증 쿠키만으로 의도하지 않은 변경 요청이 실행되는 것을 방지 |
| MP4 재생 시간 확인 | Python 표준 라이브러리 struct | 영상 파일에 기록된 재생 시간을 서버에서 직접 확인 |
| 파일 접근 제한 | 관리자 인증 및 공개 상태 검사 | 비공개 파일이 인증 없이 조회되는 것을 방지 |
| 생성 중복 방지 | 등록 요청 식별값과 DB 중복 제한 | 같은 등록 요청이 반복되어도 중복 저장되지 않도록 처리 |

## 4 검증 결과와 남은 작업

| 검증 항목 | 결과 |
|---|---|
| 백엔드 자동 테스트 | 7개 통과 |
| 실제 MySQL 연결 및 스키마 초기화 | 계정 설정 후 확인 필요 |
| 실제 DB를 사용하는 화면 통합 시연과 캡처 | MySQL 연결 후 진행 필요 |

참고로 연동 작업 중 기존 프론트 자동 테스트 18개와 TypeScript 검사·빌드도 통과했습니다. 이는 프론트 코드에 대한 참고 검증 결과입니다.

백엔드 자동 테스트는 SQLite 테스트 DB에서 수행했습니다. 인증, 권한, CSRF, 초안 저장, 공개 조건, 수정 실패 시 복원, 파일 접근 제한, 영상 구간 응답과 실제 무음 MP4 업로드를 확인했습니다. 이 결과가 MySQL의 실제 동작이나 브라우저 전체 흐름의 검증을 의미하지는 않습니다.

영상은 로컬 폴더에 저장하며, 영상 변환과 완전한 디코딩 검증은 포함하지 않았습니다. 재생 시간이 확정되지 않은 스트리밍용 MP4는 지원하지 않습니다. 실제 AI 모델 호출과 검색 기능도 이번 작업에 포함하지 않았습니다.

## 5 프론트엔드 DB 백엔드 작업 구분

| 영역 | 기존 작업 및 이번 작업과의 관계 |
|---|---|
| 프론트엔드 | 기존 React 관리자 화면과 API 요청 코드를 활용했습니다. |
| DB | 기존 MySQL 테이블 설계를 활용하고, 화면 연동용 보조 테이블을 추가했습니다. |
| 백엔드 | 기존 FastAPI 관리자 기능을 바탕으로 프론트 연동 API, 인증·검증 보완, 자동 테스트와 실행 안내를 추가했습니다. |

이번 작업은 기존 프론트엔드·DB·백엔드를 활용한 연동 및 보완 개발입니다.

Codex를 활용하여 기존 코드 분석, API 연동 코드 작성 및 수정, 테스트 코드 작성·실행, 실행 방법 정리와 활동 보고서 초안 작성을 진행했습니다. 실제 MySQL 연동 및 통합 테스트는 후속 개발 과정에서 확인할 예정입니다.
